## 1. Major（修复前不应视为深导链可长期使用）

### RV-01 durable 深导 2a 跨 chunk 同名实体 → pending slug 冲突 → Phase 3 确定性卡死

| 项 | 内容 |
|---|---|
| 证据链 | `packages/novelcraft/imports/src/entities.ts:127`（`serial` 每次 `planEntityBatch` 调用从 0 重新计数）→ `entities.ts:124`（`dedupeByEntityKey` 仅批内去重）→ `deep-import-workflow.ts:613-615`（按 `phase2BatchSize` 分 chunk 多次调用并聚合 `files`）→ `structure.ts:69-71`（`uniqueFiles` 对"重复且字节冲突"抛 `INVALID_SOURCE`） |
| 触发场景 | 同名实体（同一角色/地点）出现在不同 chunk 的 Scene 中（如第 1 与第 13 个 Scene）。两条 pending 记录同 slug（`obj-<名>-0`）、不同 evidence 字节。超过一个 chunk 容量的长篇导入大概率触发 |
| 后果 | durable Phase 3 确定性失败（`INVALID_SOURCE` → `provider_outcome_unknown` 类路径），重新授权重试也必败，workflow 永久卡死；即使越过 Phase 3，`store/src/transaction/execute.ts:851-856` 也会拒绝 writeSet 重复目标。legacy 路径（`orchestrate.ts:344-356` + `entities.ts:174` 无条件 `writeFileSync`）则静默覆盖丢失前 chunk 证据 |
| 违反条款 | 计划 P0-I1"两条编排同合同"；可用性 |
| 修复方向 | slug 序列跨 chunk 稳定：由 durable 编排持有全局 serial 并注入 `planEntityBatch`，或改为 `obj-<名>-<content-hash 前缀>` 类内容寻址；两条编排对同名实体的合并语义对齐 |
| 验证测试 | MockProvider 驱动一次超过 `phase2BatchSize` 个 committed Scene 的 durable run，两个 chunk 各返回同名新实体：断言 Phase 3 不抛 `INVALID_SOURCE`、pending 无同 slug 冲突；legacy 路径断言前 chunk 证据不丢失 |

### RV-02 durable materialize"差异即覆盖"：重调用回写手改 draft，甚至把已 adopt 的 canonical 降回 draft

| 项 | 内容 |
|---|---|
| 证据链 | `packages/novelcraft/imports/src/deep-import-workflow.ts:824-830`（`plannedFilesToWriteSet`：目标已存在且字节不同 → `expected=当前字节、output=计划字节`，即覆盖）→ `deep-import-workflow.ts:1122-1129`（每次调用 `runDeepImportWorkflow` 都重跑 materialize，不因 run 已完成跳过） |

| 修复方向 | materialize 对"目标存在且字节 ≠ 计划字节"的目标改为 CONFLICT fail-closed（保留现场、要求人工处置或新 run），只保留"字节相同 → 幂等跳过、不存在 → 创建"两种放行；至少对已离开 `draft/candidate` 状态（adopted/canonical）的目标无条件拒绝 |
| 验证测试 | durable run 完成后 adopt 一个 thread，再次调用 `runDeepImportWorkflow`：断言 `structure/threads/<slug>.md` 不被回写、状态仍为 canonical、抛 typed CONFLICT；另测手改 pending 候选后重调用不被覆盖 |

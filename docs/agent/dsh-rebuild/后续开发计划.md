## 0. 插件边界纪律(统领所有批次, 违反即 gate/测试红)

依据: 上游 deepseek-harness AGENTS.md("Plugins, not loop changes"、"Registrations are
effects"、模型可见⟺可回放、可调参数走 Config、失败要响)+ 本仓「一切皆插件」A–H 整改
+ ADR-0024 capability 三分法 + 架构铁律 1/3/4。

每项新能力必须落在正确的层与扩展点上:

1. **core 包只做加法**: 新文件 + 新导出(照 B 阶段 `1fb45fa0`、H 阶段 `commitScenesTx`
   先例); 不改既有签名/行为路径, 旧路径保留为回退; 零 `@deepseek-ai/*` 运行时依赖。
2. **dsh 适配层走 seam**: 服务读取只经 `svc(ctx,…)`; 适配器 fail-closed; 一切注册经
   `ctx.effect()/ctx.on()` 返回 disposer; 默认工具组装由 `ctx.inject(['tools'])` 驱动同步
   register，避开 rc.8 嵌套 `ctx.plugin` 静默吞错坑; jobs 走 JobKindMap 声明合并 + 遵守 AbortSignal。
3. **能力语义归位**(ADR-0024 声明表, 每能力只落笔一次): 只读→`read`;
   写待处理/草稿→`propose`; canonical adopt/status/升格→`adoptGuarded`
   (allowed-once fail-closed)。raw 写面不进公开面。
4. **新工具 = 新工具组插件**: `src/tools/<组>.ts` 经 `novelcraftToolFactory`
   (N34 隔离/toolError/封闭 output schema); 执行器只调
   `run.service.capabilities.*`/`run.service.vaults.*`; 变更副作用只经
   `run.afterMutation()`; `config.tools.<组>` 开关走 schemastery Config;
   独立插件仅经 `@novelcraft/dsh/internal` 导出。
5. **同步四处硬清单**: 隔离矩阵 `dsh/test/workspace-isolation.test.ts` MATRIX
   (含完整性自检)、preset 内联工具名清单(`preset/test/preset.test.ts`)、
   dsh README seam 矩阵、交接文档 §4.2 口径; 相关 spec/README/JSDoc 随代码走。
6. **模型可见 ⟺ 可回放**: 任何改变发给模型内容的改动(Prompt 正文/schema 注入)必须把
   prompt hash/注入模式进 journal/trace, 行为测试断言可重建。
7. **client 面零 canonical 写**: 新读面只走 `service.ui`(client-face)只读聚合/收据
   暂存; client 禁核心包值导入与裸 node:fs; UI 文案走类型化字典。
8. **Git 写收敛**: 业务 git 写只准出现在 store 事务实现的允许表内
   (check:git-writers); 新写面接 N32 目标路径级事务, 禁 `gitAdd(root)`/`-A`。

负面清单(会被拒): execute 直调 `service.<方法>` 绕 capabilities、绕过
novelcraftToolFactory 手写 defineTool、绕 ApprovalGate 的 canonical 写、手调
fireRadar/fireRag/push 不经 afterMutation、core import @deepseek-ai、改 core 既有签名、
默认组装用嵌套 ctx.plugin、改共享层不过 ADR-0018 四条纪律。

#### §2.A-探测: A1 宿主 llm seam 能力探测报告(2026-08-31, rc.8)

证据锚点: `node_modules/@deepseek-ai/dsh-llm/lib/types/types.d.ts:332-383`(GenerateOptions
完整字段面)、`types/index.d.ts`(LlmRuntime/LlmAdapter 服务面)、
`packages/novelcraft/dsh/src/llm/provider.ts`(现有适配)。

1. **GenerateOptions 无 response_format/json_schema/structured 字段**。完整字段面 =
   provider/model/reasoningEffort/messages/system/tools/temperature/maxTokens/stop/
   signal/sessionId/purpose(`purpose` 为封闭枚举 `'compaction'|'session-title'`,
   llm_step 调用不能标新 purpose)。rc.8 执行契约不支持原生结构化输出请求参数。
2. **存在 `tools?: ToolSchema[]` 原生通道**(adapters map to provider's `tools` field;
   ToolSchema={name,description,parameters:JSON Schema}), 但**不采用**: ①把内容手输出
   伪装成 tool-call 超出宿主对该 seam 的文档化用途(agent-loop 工具语义面); ②DshProvider
   现只消费 text-delta/usage/finish, 走 tools 需新增 tool-call 块解析与失败路径,
   复杂度高而结构遵循度收益未证实; ③模型可见⟺可回放纪律下伪装工具会污染 session log
   的工具语义。
3. **schema 文本注入路径成立**: `system` 槽为纯文本(adapters map to provider's system
   slot), DshProvider 已直接透传 —— OUTPUT_CONTRACT(JSON Schema 文本)进 system 尾部
   = 零宿主改动、零共享层触碰、llm-step 加法即可。
4. **A5 readiness 接入点(顺带确认)**: `LlmAdapter.listModels(provider)`(advisory,
   "absence must not become request rejection")、`LlmAdapter.resolveModel(provider,
   model, signal)`(exact-model 元数据, 不校验路由)、prepared-call 两段式
   (call-config 匹配校验 `INVALID_PREPARED_CALL`)、DirectoryRegistrationHandle
   (live/dormant provider directory)。
5. **N38(草案, 随 A2/A3 实施正式记入 specs/adjudications.md)**: schema 首轮注入采用
   **schema 文本注入**(OUTPUT_CONTRACT 进 system 槽), 不使用 GenerateOptions.tools
   伪装工具, 不触碰共享层加 response_format。去条件: 宿主 dsh-llm 契约新增
   response_format/structured 字段时重新探测; 或实测文本注入结构遵循度不足且经
   产品裁决接受 tools 通道复杂度。

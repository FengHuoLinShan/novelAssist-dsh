# 客户端阶段 B 验收快照(宠物/收件箱 client-module)

- 日期: 2026-08-14
- 范围: @novelcraft/client 的 DSH web client-module(设计文档 §9/§17 的宠物四态 +
  收件箱卡片/四动词/键盘流); 写作台四模式/剧情地图留后续迭代
- 实现: `packages/novelcraft/client`(双面包: node 半身 RPC 通道 + 浏览器半身 UI)

## 架构与安全边界

- 数据路径: 浏览器 → `connection.rpc.call('/novelcraft', …)`(authority=loopback)
  → 宿主处理器 → `@novelcraft/assistant` 确定性函数(读 `.assistant/signals/*.json`)。
- **四动词只记录决定**(assistant.act); adopt 类资产写入不走 UI 通道 —— 由助手
  agent 经 DSH approval 执行(§9 fail-closed)。未绑定工作区 → capability 缺省, 不炸通道。
- wire 契约唯一权威 = `src/wire.ts`(纯类型+常量, 双端共享, 无运行时依赖)。

## 端点

| 端点 | 语义 |
|---|---|
| `watch/state` | 宠物四态数据(bound/open/attention/threshold/radarRunning) |
| `inbox/list` | 收件箱卡片(作者语言字段: 标题/雷达/严重度/证据/建议动作/状态) |
| `inbox/act` | 四动词(accept→adopt 指引 / reject/modify 必带理由进校准 / defer) |

四态: 待确认(open≥threshold, N3=5)> 忙碌(novelcraft-radar job 运行中)> 微光 > 静默。

## 构建链(D21 锁 rc.6)

- 宿主半身: tsc → dist/index.js(Loader 装载); 浏览器半身: tsdown + vendor 的
  DSH 共享预设(`build/tsdown.client.ts`, closure-factory + CSS Modules 内联 +
  纯度门禁; externals = platform 模块表 react/ui-primitives/ui-slots/…)。
- **实现期发现(已记录)**: client-modules 扫描按入口名 `require.resolve(
  '<pkg>/package.json')`, 因此插件包 exports 必须暴露 `./package.json`,
  且 profile 行必须用裸包名(绝对路径不被扫描为 client 包)。

## 复现(依赖: 已装 DSH rc.6 CLI 的目录 + playwright chromium)

```sh
# 0. 仓库内先构建: npm run build --workspaces(tsc + tsdown; dist 不提交, 属构建产物)
# 1. 拷贝 14 个 @novelcraft 包(dist+package.json)进 DSH 安装树 node_modules/@novelcraft/
# 2. patch 文件(顶层数组):
#    - insert: [ {id: novelcraft, name: "@novelcraft/dsh", config: {...}},
#                {id: novelcraft-client, name: "@novelcraft/client"} ]
# 3. DSH_HOME=<scratch> dsh --profile web --patch patch.yml --port 18099
# 4. curl / | grep __DSH_BOOT__  → 含 @novelcraft/client
#    curl /plugins/@novelcraft/client/client.js → 200
# 5. node scripts/m5-client-smoke.mjs(仓库内)
```

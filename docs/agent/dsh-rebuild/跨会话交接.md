1. **核心包零 DSH 运行时依赖**: `packages/novelcraft/*` 的 13 个核心包是纯 TS 确定性库,
   不 import 任何 `@deepseek-ai/*`; DSH 接触面唯一收敛在 `@novelcraft/dsh`。
2. **文件是唯一真相**: 每书一个 git 仓库(vault); 资产 = frontmatter 文件 + git commit,
   派生索引任何时刻可全量重建; git 本身就是回滚面。**不另建数据库/队列**。
3. **adopt 必过 approval(fail-closed)**: 采用类资产写入由助手 agent 经 DSH approval
   (allowed-once 只放行一次); 客户端 RPC 通道(authority=loopback)只读信号 + 记录决定, 不写资产。
4. **核心包不得回头改接口, 只做加法**: 新文件 + 新导出; 阶段函数保持可测
   (MockProvider/MockApproval 注入)。
5. **内容手受控**: llm_step 由确定性业务工作流编排, 带 output_schema/预算/超时/journal;
   普通 LLM 输出只进待处理/临时预览。
6. **Key 与 secret**: Key 只走 DSH credentials; `.assistant/llm.yml` 只存模型名与参数(N5)。

- 包结构: `packages/novelcraft/*` = npm workspaces。13 核心包 + `dsh`(唯一 DSH 接触面)
  + `client`(双面包)+ `trace` + `preset`。**核心包不得回头改接口**。
- 安全边界(硬): UI 四动词只记录决定(assistant.act); adopt 类资产写入必须由助手
  agent 经 DSH approval(fail-closed)执行 —— 客户端 RPC 通道(authority=loopback)
  **不写资产**。Key 只走 DSH credentials; llm.yml 只存模型名(N5)。
- 客户端数据流: 浏览器 → connection.rpc.call('/novelcraft', …) → 宿主处理器 →
  assistant 确定性函数(读 `.assistant/signals/*.json`, 文件唯一真相)。wire 契约
  唯一权威 = `packages/novelcraft/client/src/wire.ts`。
- 资产引用口径: 所有 `related_*_ids` / `*_id` 统一为**裸 slug 引用**(指向
  `world/objects/*.md`、`chapters/*.md` 或 `structure/*` 的稳定 slug), 不再是 UUID;
  引用完整性由 store 写入时 `resolveAsset()` 解析 + 同 vault 校验承接, **没有数据库外键**。
- cordis inject 门禁按 fiber 生效 → 所有服务读取走 `svc(ctx, name)`(dsh/src/ctx.ts),
  缺失服务降级/fail-closed, 不炸插件。
- dist 是构建产物且被 .gitignore 忽略; `build/` 目录名被 .gitignore 命中, 构建工具
  目录须用 `build-tools/`(client 包已如此)。
- 测试约定: vitest 行为契约, 断言注释引规则/裁定编号; 全仓 `npm test` / `npm run typecheck`。

## 6. 已踩过的坑(实现期发现, 勿重踩)

1. `--patch` 覆盖层 = 顶层 YAML **数组** of PatchOptions(`- insert: [...]`)。
2. client-modules 扫描按入口名 `require.resolve('<pkg>/package.json')` →
   插件包 exports 必须暴露 `./package.json`, 且 profile 行必须用**裸包名**
   (绝对路径不进 boot 清单)。
3. 跨树加载插件必须与 CLI 同 node_modules 树, 否则双 cordis 实例破坏 Service
   symbol 注册(e2e 用「拷入安装树」规避; 发布后 `dsh plugin add` 天然满足)。
4. domain zod 校验发生在 durable 读边界(重开时), 写入期不即时拒绝。
5. dsh-tools 的 defineTool: 参数/输出 schema 必须内联字面量(const 泛型推断),
   输出 object 需 `additionalProperties: true`(dsh 强制开放根)。
6. schemastery 无 `.optional()`, 用 `.default()`; 可选服务不能依赖 inject 门禁。
7. 子代理/工作流 agent 的 provider 路由: kimi-coding 需 `KIMI_CODING_API_KEY`。
   **已解决(2026-08-14)**: rc.6 解析机制为「启动环境 env 优先、DSH credentials 文件
   (`$DSH_HOME/.credentials.yaml`)其次、.env 兜底」, 不再要求把 key 放进 harness
   进程环境。key 已通过 Models 页写入 credentials 存储, 实测与运行中 harness 相同的
   解析路径: `credentials.resolve("KIMI_CODING_API_KEY")` → source=file(72 字符),
   `describe` → configured: true; 文件 watch(100ms debounce)自动刷新, 无需重启。
   kimi-coding catalog 模型: `kimi-for-coding` / `kimi-for-coding-highspeed` /
   `k3` / `k3-256k`。注意: 余额悬浮球 llm-balance 插件只配了 deepseek,
   不会显示 kimi 余额(与 key 注入无关)。

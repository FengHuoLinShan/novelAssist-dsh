## 3. 后台任务与 AI 工作流(已盘点)

### 3.1 任务队列能力(infrastructure/tasks)

- PostgreSQL async_tasks + SELECT ... FOR UPDATE SKIP LOCKED;无 Redis/Arq。
- novel_id 一等不可变隔离键(FK projects.id ON DELETE CASCADE);lease 三键 fence(心跳/终态)。
- 状态机 pending/running/done/failed/cancelled;recovery_policy: auto_requeue/manual_resume/restart_origin/never_retry。
- stale 检测(心跳 30s / 判定 120s)、auto_requeue 退避(1/2/4/8/16/30s)、retry_transient_llm_errors(任务内关传输重试, worker 重排一次, attempt≤2)。
- 进度 progress(float)、checkpoint(handler 确定性阶段边界 commit + FOR SHARE→lease fence)。
- coalescing_key(SHA-256) 唯一部分索引;结果 _ 前缀私有字段剥离;apply 白名单投影 + revision CAS。
- worker 组合根: run_worker.py(预检/提交守卫/启动 reconciler);task_runtime.py 注册 8 个模块 tasks。
- API: GET /api/tasks/{id}(轮询/available_actions)、cancel、retry;业务任务禁止通用 POST /api/tasks。

### 3.2 LLM 基础设施(infrastructure/llm + project seam)

- open_project_llm_client() / create_project_snapshot_llm_client()(secret-free 快照: provider 固定、Key 轮换后重解析、endpoint/extra 漂移 fail-closed)。

- generate_structured: json_object 模式 + 多策略解析 + Pydantic 校验 + 修复预算(2 fix + 截断扩 token + format_repair)。

- ManagedLLMStep: read/suggest/draft/act-with-confirmation 权限,autonomous 拒绝;journal/provenance/超时/预算守卫。

### 4.3 核心数据语义(不变量)
- display_state 投影 review/active/archived ↔ 待处理/已采用/历史; 领域派生, 不替代原始 status。
- 原始状态机: 领域 draft/candidate/canonical; 正文 draft/published/candidate/canonical/deprecated(published 不可原地改); 融合建议 pending/adopted/dismissed/stale; 任务 pending/running/done/failed/cancelled。
- revision/CAS: head 先锁再 base_revision_id CAS; revision (novel_id,version_number) 唯一 + idempotency_key 幂等; 复合 FK 防跨项目; DB trigger 拒绝更新。
- 回滚三层: text_archive(主) + entity_revisions + delta_log; memory 历史只由带 Scene 锚点的 MemoryEvent 确定性重放。
- 可见性: knowledge_visibility_policies/reader_reveal_policies; rag_chunks.visibility; core_entities.reveal_level; scene_summary_checkpoints 防剧透截止。
- 授权/审计: context_confirmations(+asset_refs)、context_snapshots、evidence_links、account_security_events/consents、import_workflow_runs.authorization_snapshot、interaction attempts 的 secret-free LLM snapshot。
- novel_id 隔离: NovelMixin FK CASCADE; async_tasks.novel_id 不可变(before_update 拒绝); 跨模块表刻意不建硬 FK; 查询/API 显式过滤。
- owner 授权: projects.owner_id→accounts.id; 浏览器路径 = principal + owner 双门禁; 凭据 (owner_id,provider_id) 隔离。
- 采用边界: AI 输出先入 suggestion 队列/candidate, 作者采用后写领域资产; 自动流水线仅持久化授权后可回滚结果。
- 历史: 不硬删除; deprecated/ignored/merged/rolled_back 进历史隐藏。
- HTTP 读后写一致性: request-owned transaction 响应开始前 commit; 流式/detached work 独立 session。
- 已移除表非契约: chapter_cards、memory_records、entity_candidates/aliases、geo_*、timeline_events、review_reports、旧 map_* 17 表。

4. 世界: 对象/别名/关系待处理(采用/编辑后采用/设为别名/合并/忽略/回滚);生成中心(chat/convergence/exploration/检修/结构化建议/采纳包);world.ask;世界书(页面/草稿/发布影响/revision 恢复);简介自动维护;地图册(规划→生图→采用/重试/费用确认)。

6. 检索: RAG 搜索(候选+来源证据)/重建/重试/prewarm;上下文确认(confirmAiReference 前置门禁)。
7. 项目级: 智能去重扫描→分组确认。

### 5.2 RP 路径
1. 首屏"我是 RP 用户"→ 自然语言开场(世界/身份/愿望)。
2. 持续故事(SSE 流式, checkpoint 512字符/2s, 断线恢复, last-event-id 续传)。
3. 重新生成/编辑/分支选择(不可变 sibling, 代码级选中路径)。
4. 自动回顾(分段概要+总回顾 revision, 用户可修正)。
5. 看海循环(有界自动推进, 非自治 Agent);停止/保留残段/继续。
6. 导出;旅程列表/恢复;心跳/离开记账。

### 5.3 横切体验
- 统一: 触发→task_id→轮询(1500ms, 页面隐藏暂停, in-flight 去重)→进度卡(作者语言标签)。
- 恢复: localStorage novel_active_workflows_v1 + manager.recover;深度导入 resume/abandon。
- 错误: 脱敏文案(sanitizeTaskErrorMessage);部分完成/降级提示;空态;取消保留已保存结果。
- 保护: island onLeave 停止轮询、useLeaveGuard 路由守卫、草稿备份、beforeunload。

## 0. 使用规则与不变量

- **能力契约**: 用户能完成的任务、稳定入口、输入/输出和可见结果。
- **行为契约**: 隔离、采用/审批、校验、并发冲突、恢复、回滚、失败降级和用户反馈。
- 状态: `≈` 语义已对齐; `△` 部分对齐或有意替代; `✗` DSH 缺口; `+` DSH 新增;
  `?` 仅 dirty working tree 候选。
- M4 已选择文件 + git + DSH seam, 因此 HTTP API、PostgreSQL schema、Vue DOM/wire 不再是
  逐项兼容目标; 需要保留的是经产品裁决选中的能力/行为语义。
- 无论实现形态如何, 工作区隔离、密钥保护、历史与回滚、LLM 输出 schema、采用授权和
  fail-closed 行为不得弱化。
- 作者路径是否保留完整 web 工作台、RP 是否继续属于 M4 产品范围, 尚未裁决; 在裁决前不能
  把它们从差异台账中删除。
- dirty working tree、过时状态文档和计划不作为“已实现”证据; 证据优先级为已提交实现 +
  行为测试 → 已提交权威契约 → 候选实现/ADR → 计划。

### 4.3 核心数据语义(不变量)
- display_state 投影 review/active/archived ↔ 待处理/已采用/历史; 领域派生, 不替代原始 status。
- 原始状态机: 领域 draft/candidate/canonical; 正文 draft/published/candidate/canonical/deprecated(published 不可原地改); 融合建议 pending/adopted/dismissed/stale; 任务 pending/running/done/failed/cancelled。
- revision/CAS: head 先锁再 base_revision_id CAS; revision (novel_id,version_number) 唯一 + idempotency_key 幂等; 复合 FK 防跨项目; DB trigger 拒绝更新。
- 回滚三层: text_archive(主) + entity_revisions + delta_log; memory 历史只由带 Scene 锚点的 MemoryEvent 确定性重放。
- 可见性: knowledge_visibility_policies/reader_reveal_policies; rag_chunks.visibility; core_entities.reveal_level; scene_summary_checkpoints 防剧透截止。
- 授权/审计: context_confirmations(+asset_refs)、context_snapshots、evidence_links、account_security_events/consents、import_workflow_runs.authorization_snapshot、interaction attempts 的 secret-free LLM snapshot。
- novel_id 隔离: NovelMixin FK CASCADE; async_tasks.novel_id 不可变(before_update 拒绝); 跨模块表刻意不建硬 FK; 查询/API 显式过滤。
- owner 授权: projects.owner_id→accounts.id; 浏览器路径 = principal + owner 双门禁; 凭据 (owner_id,provider_id) 隔离。
- 采用边界: AI 输出先入 suggestion 队列/candidate, 作者采用后写领域资产; 自动流水线仅持久化授权后可回滚结果。
- 历史: 不硬删除; deprecated/ignored/merged/rolled_back 进历史隐藏。
- HTTP 读后写一致性: request-owned transaction 响应开始前 commit; 流式/detached work 独立 session。

### 5.2 RP 路径
1. 首屏"我是 RP 用户"→ 自然语言开场(世界/身份/愿望)。

### 6.6 P0 对齐切片: 深度导入授权、采用与崩溃恢复

先分清三个不能互换的概念:

1. **运行范围授权(run authorization)**: 作者同意在指定书/章节范围、执行画像和成本边界内
   调用 LLM 并产出候选。可持久化的是授权事实与范围, 不是可重放的审批 token。
2. **规范资产采用授权(canonical adoption authorization)**: 作者同意把一组已定型候选写入
   canonical 资产。DSH 的 `allowed-once` 只对本次精确写集有效, decision/token 不得落盘。
3. **恢复证据(recovery proof)**: checkpoint/manifest、输入与结果 hash、事务 id/probe、commit
   evidence。它只能证明“做过/没做/未知”, 不能自行生成新的用户授权。

#### 6.6.2 下一步重构的最小合同

1. run identity 至少绑定工作区/书、章节 scope、输入 fingerprint、execution profile、contract
   version 与 plan digest; 任一变化不得续跑旧 run。
2. 范围授权记录与 canonical 采用授权分层。授权记录可审计/恢复; `allowed-once`
   decision/token 永不序列化、缓存或重放。
3. 生成阶段只产候选与可验证 receipt; canonical 写必须从精确候选 hash 和 expected target hash
   构造写集, 不能让 LLM 输出直接落 canonical。
4. provider outcome unknown 必须停住; 仅对实际 remaining/unknown 批重新展示范围和可能成本,
   获得新运行授权后才重试。
5. apply 恢复只有三条路: `completed → 补状态`; `none → 回 waiting + 新审批`;
   `unknown → 保留现场 + 人工处理`。禁止第四条“直接再写一次”。
6. resume 必须先验证 run identity、已完成 artifact/receipt 和持久 intent; stale generation/owner
   不能提交 checkpoint 或 canonical 写。
7. abandon 必须给出可验证 cleanup summary: 新建候选可移除, 已采用资产走可回滚/软废弃,
   与其他 workflow 共享或后续编辑过的资产不得误删。
8. 用户结果合同统一为 `adopted / review / not_adopted / unknown`, 每项保留 provenance、
   rollback 能力和下一动作, 但默认 UI 不暴露 raw id、manifest 或 token。

### 6.7 P0 对齐切片: 能力面与非自治边界

这轮不要求两边长成同一套 API。先用“副作用等级 + 授权来源”统一语义, 再决定 Web
业务工作流和本地 agent 宿主分别如何实现。`read/propose/adoptGuarded` 是 DSH 候选代码的命名,
不是足够精细的行为合同。

#### 6.7.1 统一副作用等级

| 等级 | 允许副作用 | 授权来源 | 共同硬边界 |
|---|---|---|---|
| `read` | 不修改创作资产; 可有明确声明的访问日志 | 已绑定 principal/workspace | 不得借“读取”刷新候选或 canonical 状态 |
| `derived` | 可重建的索引、缓存、trace、健康诊断 | 无采用授权; 仍须 scope | 删除后可从事实源重建, 不能成为创作事实源 |
| `propose` | pending/draft/candidate、建议、任务结果 | 已授权的运行范围 | 不得写 canonical 内容或 adopted/published/deprecated 等 canonical 状态 |
| `author_edit` | 作者指定资产的窄字段编辑 | 当前作者请求, 或可证明由作者预先给出的精确操作 | 固定字段、严格 schema、expected hash/CAS、事务、provenance; 禁通用 LLM patch |
| `adopt_guarded` | canonical create/update/merge/adopt/restore/archive 等内容或状态变化 | 新鲜 `allowed-once`, 或另行定义的窄持久自动流水线 grant | 审批前冻结精确写集; 审批后重验 CAS; 拒绝/取消/不可用均零写 |

`derived` 与 `author_edit` 不必成为新的 TypeScript namespace。保留候选实现的三个 namespace
即可, 但能力清单、测试和审计必须按上述五类标注真实 effect, 不能用代码分组掩盖副作用。

#### 6.7.4 下一步重构的最小合同

1. 每个 agent tool 和 package capability 都登记 effect、scope、authority、允许的资产状态、
   provider/文件/索引副作用、失败结果与 rollback; 未登记能力默认不可用。
2. 任何文件、provider 或业务服务访问前先解析绑定 scope。源系统绑定 principal/owner/`novel_id`;
   DSH 绑定 session/canonical vault, 调用方 root 只能做一致性断言, 不能改目标。

   workflow 所有; 通用 LLM 输出不得携带或升级写权限。
4. `read/derived/propose` 不能触发 canonical 内容或状态变化。自动修复、archive、restore、merge、
   alias 等只要改变 canonical, 都按 `author_edit` 或 `adopt_guarded` 处理。
5. `author_edit` 只保留可证明的作者定向操作: 固定目标/字段、严格 schema、expected hash/CAS、
   单事务和 provenance。来源不明的本地 queue 仍按 agent 写请求处理, 不能免审批。

   scope 与 CAS 再执行。decision/token 不落盘, 恢复语义沿用 §6.6。
7. DSH 主导出和 tool registry 不暴露 raw canonical writer; host-only `./internal` 使用白名单和
   distribution test。core 包直引属于受信任同进程代码边界, 用 lint/审查约束, 不宣传为沙箱。
8. 最小门禁包括: 工具不直调 Service 写方法的静态审计、公开导出审计、workspace 越权负例、
   所有 guarded transition 的拒绝零写、propose 状态审计、author-edit 例外专项测试。
9. dirty 候选只有在固定 commit、`npm test` 与 `npm run typecheck` 全绿后才可把本节结论从
   “候选”升级为“已实现”; 当前 typecheck 红, 仍不得升级。

### 6.8 P0 对齐切片: 事务、提交点与外部 blob 一致性

先分清五个不能用“有 Git 历史”一笔带过的概念:

1. **操作原子性**: 本次完整 writeSet 要么全部可见, 要么全部不可见。
2. **并发冲突**: 计划/审批后发生的目标内容、HEAD、scope 或 owner 变化必须拒绝覆盖。
3. **崩溃恢复**: 进程死亡后能证明未开始、部分写、已提交或未知, 并按既定策略收敛。
4. **产品回滚**: 已成功提交后由作者执行的历史恢复; 它不同于未提交事务的自动回滚。
5. **外部 blob 一致性**: 数据库/Git 之外的图片字节与其元数据引用必须可验证、可补偿。

#### 6.8.3 下一步重构的最小合同

1. 以**用户可见副作用**而非函数所在包决定事务边界。canonical、candidate、draft、导入记录、
   review receipt 只要共同构成一次用户操作, 就进入完整 writeSet; 可重建索引/缓存可例外。
2. 所有创作写能力在首写前声明完整目标、expected bytes/absent、必要的 expected HEAD 与输出。
   关系日志、祖先链、旧路径删除、receipt 都是 writeSet, 不能事后另写。
3. 任何创作 commit 前发现共享 index 已有 staged 必须 fail-closed, 保留并提示作者处理;
   精确 `gitAdd(paths)` 不能作为替代证明。禁止普通 writer 调无 path 的 `gitCommit`。
4. provider/LLM/图片解码等慢外部工作在事务外完成; 产物先冻结 hash/bytes。事务内不等待外部
   服务, 写前重验 scope、权限、目标 CAS 与计划身份。
5. 事务恢复策略与能力权限分离: proposal/draft 可在持久产物已验证时自动补完或安全回滚;
   canonical adopt 未提交只能回滚并取得新审批; 已提交只补状态, 永不复用 token。
6. commit point 唯一且可探测。DSH 以可达的唯一 tx commit 为事实终点; 后续 receipt/index
   收尾失败返回 recovery-required/committed-pending-finalization, 不能返回可盲重试的普通失败。
7. no-op/重复调用统一返回 `unchanged` 或既有 receipt; 不新增 commit、不重新审批、不把核心
   helper 的空 writeSet 拒绝直接泄露给作者。
8. blob 使用不可变 attempt/version 路径并保存 byte hash/size/type。元数据提交前验证 blob;
   元数据失败后引用复核再删 orphan, 删除失败进入可重试 cleanup 状态; 已提交元数据发现
   blob 缺失时显示可恢复错误, 不把资产当正常完成。
9. 对不遵守锁的编辑器诚实保留边界: 多复核点降低风险, 但 check→rename 不是物理 CAS。
   UI 应在短 apply 窗口提示同目标不要并发保存; 检测到冲突保留作者字节并停止。
10. 新门禁必须按公开能力追踪实际 writer: tool → capability → service → core 写面。至少负测
    pre-staged、首文件后崩溃、ref 竞争、commit 后 receipt 失败、blob orphan/missing 和 no-op;
    仅搜索 `git add -A` 或仅测试 `executeTransaction` 不足以关闭覆盖缺口。

### 6.9 P1 对齐切片: 长任务生命周期与作者恢复反馈

先分清三层, 避免把“内核可恢复”直接当作“作者能恢复”:

1. **运行时执行句柄**: 进程内 job/AbortSignal, 负责存活期观察与请求停止; 进程退出后不是真相。
2. **耐久工作流事实**: task row 或 run manifest/receipt/commit, 负责重启后证明已完成、未完成或未知。
3. **作者投影**: 用作者语言呈现当前状态、完成/剩余、成本与固定动作; 不能要求作者读 manifest、
   trace、job id 或内部枚举。

#### 6.9.1 当前事实差异

| 场景 | ai-writing-assist `ee3c1451d` | novelAssist-dsh 已提交 `828578b8` | novelAssist-dsh dirty 候选 | 对齐结论 |
|---|---|---|---|---|
| 执行模型 | 任务提交立即返回 task id; worker 独立执行, 页面离开不取消 | deep-import 是同步工具, 最长 timeout 1 小时; 只有雷达使用 `ctx.jobs` | deep-import 仍同步, 仅贯通 `exec.signal`; run manifest 不等于后台执行句柄 | 对作者级长任务, 同步工具仍未对齐“可离开再回来” |

| 作者恢复位置 | task receipt 按 project 持久化; 刷新恢复最新活动项, 失败/恢复卡默认展开, 可关闭 | client 没有创作 workflow 列表/任务卡; 宠物忙碌只代表雷达 | run 目录可枚举, 但没有 loopback 只读端点或 UI | 必须从 vault 耐久事实列出未完成 run, 不能依赖旧浏览器 local state |
| 动作权威 | 后端投影是目标合同; deep-import 专用 controller 缺字段时零动作 | 无动作投影 | 无动作投影 | 源共享 normalizer 仍有按状态猜动作的兼容 fallback, 这也是待清理残余, 不应复制到 DSH |
| 信息暴露 | 私有 checkpoint key 不进 status API; 技术错误转作者语言, 详细审计渐进展开 | 工具 JSON 主要给 agent, client 无任务详情 | manifest/trace 含内部 ids、hash、状态机字段 | 新投影只给作者所需摘要; 原始 manifest/trace 保持诊断次级面 |

`ctx.jobs` 仍有价值, 但只应作为**当前进程的控制器**: start/kill/wait/完成通知。其本地契约明确
不持久化, snapshot 也没有增量 progress; 因此重启后的状态、剩余批次和恢复动作必须从 run
manifest/commit 重建。DSH `goal` 是会话级整体目标, 当前 NovelCraft 未接线, 也不应拿来冒充
单次导入的 operation receipt。

#### 6.9.2 最小状态/动作投影

内部枚举不必照抄源系统; 但同一耐久事实必须确定性投影为下表行为:

| 耐久事实 | 作者语言状态 | 允许动作 | 禁止行为 |
|---|---|---|---|
| run 已计划, 当前进程尚未/正在执行 | 等待处理 / 正在整理, 显示阶段与完成批次 | `stop`(有活跃句柄时)、`dismiss` 仅隐藏卡片 | 隐藏后删除 run; 根据无 heartbeat 猜成功 |
| `waiting_approval` | 等待你确认本次采用 | `review/approve/reject` 走当次 ApprovalGate | 复用旧 allowed-once; 自动采用 |
| `provider_outcome_unknown` | 本批结果未知, 可能已产生费用; 已完成批不会重做 | `reauthorize_remaining` 或 `abandon` | 自动重调 provider; 把它显示成普通失败/可免费重试 |
| `apply_probe_unknown` / 未收敛 intent | 保存结果需要检查, 已保留现场 | `inspect/recover` 进入受控诊断; 普通作者可 `dismiss` 但不改变事实 | 盲重写、盲 rollback、显示“未保存” |
| commit 已成、状态收尾未成 | 内容已保存, 正在修复状态 | 自动 finalize; 必要时 `inspect` | 再次提交或重新审批 |
| completed 且有 conflict/rejected/degraded | 整理完成, 有待处理项 | `open_results/dismiss` | 仅显示绿色成功并吞掉待处理数 |
| completed | 整理完成 | `open_results/dismiss` | 自动删除审计/history |
| 明确停止且无未知 provider/apply | 已停止, 已保存完成部分 | `continue/abandon/dismiss` 按 run policy | 把 stop 等同 abandon 或删除已提交 artifact |
| 不兼容输入/profile/contract | 当前任务不能继续 | `restart_origin` 或新 run; 保留旧 run | 修改旧 run identity 后硬续跑 |

#### 6.9.3 下一步重构的最小合同

1. 每个长创作操作在首个慢调用前返回稳定 `operation_id/workflow_id`; 同一 id 关联 DSH job
   与耐久 run, 但后者才是真相。后台 job 可复用现有 `ctx.jobs`, 不新建队列/数据库。
2. 增加一个只读的 operation projection seam, 从 manifest/receipt/commit 构造固定
   `status/phase/completed/total/remaining/cost/warnings/available_actions`; 不直接返回 manifest。
3. `available_actions` 由领域状态机产生, client/agent 不根据时间、错误字符串或内部状态猜动作。
   未知字段/未知状态 fail-closed 为“需要检查”, 不默认 `retry`。
4. deep-import 工具不得在失败时清空已知 workflow id。结构化返回至少保留
   `status/workflow_id/completed_batches/remaining_batches/recovery_required`, message 只作展示。
5. 长操作默认后台启动并快速返回; 若暂时保留同步工具, 也必须另有 list/status/resume/abandon
   粗粒度能力, 让进程重启后可恢复, 不能只靠 agent 猜“用同参数再调一次”。
6. stop 只请求终止当前执行句柄; 随后由 manifest/probe 判定 completed、outcome unknown 或安全停止。
   abandon 是另一项显式领域动作, 只改变 run 可继续性/工作流自有候选, 不删除 Git 历史。
7. 启动/HMR/session 恢复时枚举未终结 run 并先收敛 intent; client 重开后从只读投影恢复卡片。
   浏览器 local state 只能保存展开/关闭偏好, 不能是 operation 身份唯一来源。
8. 不提供虚假 ETA。显示阶段、已完成/总批次、当前动作、已知已消费/剩余预算; 没有可证百分比时
   使用不定进度。
9. 自动 retry 只适用于零外部副作用或能证明未调用 provider 的瞬时失败;
   `provider_outcome_unknown` 继续保持 dirty 候选的重新成本授权合同。
10. 错误默认作者语言; hash、txid、raw manifest、trace 与 Git 修复说明进显式诊断入口。至少覆盖
    页面离开/进程重启、stop 竞争、provider unknown、apply unknown、commit 后收尾失败、
    completed-with-warnings、动作拒绝零副作用和 390px 任务卡 E2E。

### 6.10 P1 对齐切片: 作者审查、采用与返回创作位置

这条链路只需区分五层, 不需要再造一个通用 review framework:

1. **候选资产**: AI 产出的对象、关系、章节、地图页等可验证文件/记录, 它的状态才是待处理真相。
2. **注意投影**: Today/inbox 只把候选、冲突或建议投影成作者任务, 可重建, 不拥有资产状态。
3. **作者决定**: 领域动作及编辑草稿, 例如采用、并入、设为别名、分别保留、返修或驳回。
4. **规范写入**: 审批、CAS 与事务成功后的唯一 commit point; 失败时候选仍待处理。
5. **作者回执**: 用名称、数量和创作位置说明结果; raw id/hash/trace 只进诊断入口。

#### 6.10.2 下一步重构的最小合同

1. 候选资产状态是唯一待办真相。新增一个**只读投影函数**即可, 从现有

    核心包绿灯不能把本域升级为对齐。

### 6.11 P1 对齐切片: 采用后上下文就绪与生成消费

“已采用”之后还有三个不同的完成点, 不能都折叠进 canonical commit:

1. **正式资产已提交**: DB transaction 或 Git commit 已成功, 作者事实源已经改变。
2. **派生读取已追平**: RAG、synopsis、activity/radar 等可重建投影已刷新, 或能明确报告降级。
3. **本次生成上下文已冻结**: 真正送入 outline/writing/map 的来源及 hash、裁剪和警告已保存。

第一点失败时采用失败; 第二点失败时采用仍成功但上下文降级; 第三点缺失时, 即使生成成功也
无法证明它是否消费了刚采用的资产。下一步重构只需把这三个时钟说清楚, 不把派生索引塞进
canonical transaction, 也不新增事件总线或通用状态子系统。

#### 6.11.2 下一步重构的最小合同

1. 复用现有 `syncRagIndex`、`rebuildIndex`、`source_content_hash` 与 Git commit, 不建新数据库、
   daemon 或事件总线。canonical transaction 仍只提交事实资产。
2. 把 post-commit 收尾放到 `adoptGuarded` capability 的唯一出口, tool 只投影 receipt;
   `store_adopt`、chapter adopt 与后续 guarded merge/alias 不得各自复制 hook。结构读面不需要的
   派生步骤返回 `not_applicable`, 不做无意义刷新。
3. 本地 lexical `syncRagIndex` 是确定性增量文件操作, 首版可在 commit 后同步执行。失败时返回
   `canonical=committed, context=degraded, retry_action=rag_sync`, 不抛成 adopt failure;
   embedding 继续异步/可降级, 不阻塞作者写入。
4. `ragSearch` 在返回 hit 前必须保证当前源同步, 或逐 hit 重读源文件并核对
   `source_content_hash`; 最短实现优先复用现有 sync 做 read-through refresh。刷新失败时返回
   `degraded=index_stale` + 空/已验证 hits, 禁止静默使用旧文本。
5. map-atlas 等生成消费者只接收已验证 hit; 来源在 LLM 前再次冻结
   `kind/ref/source_hash`。若文件在编译后变化, apply 前按现有 CAS/context hash 拒绝或重编,
   不把旧来源写成当前证据。
6. 不强迫所有流程改走一个通用 context framework。writing proposal、map-atlas 与后续 world
   生成可以保留各自最短确定性 assembler, 但都返回同一最小 usage 形状:
   `included_refs[{kind,ref,source_hash}] / omitted / warnings / context_hash`。
7. adopt receipt 最少分开 `canonical.status/commit/target` 与
   `context.status=ready|degraded|not_applicable`, 再带 `warnings/retry_action`。作者默认只看
   “已采用”“参照已就绪/待刷新”和重试按钮, raw hash/index stats 留在诊断面。
8. 重试只能重建派生索引、embedding 或 radar, 不重新执行审批/adopt。重启后直接从 vault 真相
   运行同一个 sync 即可; 不为可重建派生结果创建 durable run。
9. `@novelcraft/context` 在有真实 consumer 前只算可用原语, 不算已对齐能力。接入时再补
   source refs/hash 与 confirmation receipt, 不先扩展一套抽象 loader/plugin 体系。
10. 最小行为测试覆盖: capability 直接采用也触发同一 finalizer; sync 失败时 commit 保留且回执
    degraded; 外部改/删源后 search 不返回旧 chunk; map-atlas 不消费 stale hit; embedding 失败仍可
    BM25; retry 不产生第二个 adopt commit; writing/atlas snapshot 记录实际 refs/hash; client 显示
    “已采用但参照待刷新”并可只重试派生步骤。

建议的最小回执示意, 字段名可随现有 wire 收敛, 语义不可再折叠:

```json
{
  "canonical": { "status": "committed", "commit": "...", "target": "world/objects/x.md" },
  "context": { "status": "degraded", "warnings": ["参照检索待刷新"] },

```

源项目可复用的合同不是数据库形态或 Activation Profile UI, 而是四个可观察行为:

2. **确认绑定实际输入**: 作者确认的选择必须和 provider 收到的内容共享同一来源清单与 hash。
3. **省略可解释**: 预算、Top-K、无关联或显式排除都进入 warning/omission, 不能静默消失。
4. **漂移 fail-closed**: 正文或任何已选来源在 provider 前后、采用前发生变化, 候选保持待处理并要求重新生成。

| 生命周期资格 | canonical/adopted 可进入; deprecated/candidate 不进入; working 只有显式模式才进入 |
| 时间/范围边界 | 目标章后的 Scene 不进入; 相关当前/历史 Scene 可进入 |
| World/Bible 相关性 | relation-linked 或显式 ref 进入; 无关页面不因存在而全量注入 |
| proposal 凭据 | record 与 tool response 含同一 run id、refs/hash、omission/warning; 作者选择绑定该 run |
| provider 前漂移 | base 或任一来源变化后不调用 provider、不写 candidate, 返回重新生成动作 |
| provider 后漂移 | 模拟 LLM 期间改源; candidate commit 为零, 原文件不变 |
| 采用前漂移 | 普通 writing candidate 也因 base/context 不一致拒绝采用并保持 pending |
| 稳定重试 | 输入未变化时 included refs 的顺序和 context hash 相同 |
| 作者语言投影 | client/tool 默认显示来源类别、遗漏与恢复动作, 不暴露 raw hash/内部枚举 |
| 大纲后续接线 | 只有公开 outline 工作流使用同一 receipt 并具备 apply 前复核后, generation/analyze 才从“原语”升级 |

#### 6.12.4 尚待裁决, 不预建

| 裁决项 | 当前保守默认 | 何时升级 |
|---|---|---|
| canonical 还是 working 默认 | canonical/adopted; draft 必须显式 | 明确定义 draft 是作者工作事实并补切换 UX 后 |
| World/Bible 自动范围 | 只取 relation-linked + explicit refs | 真实作品证明漏召回后再加检索/Activation Profile |
| POV 知识边界 | 不声称对齐; 没有模型时至少禁止未来 Scene | DSH 有稳定人物 knowledge/reveal 模型或明确移除裁决后 |
| 预算 | 只预算 context, 先复用现有约 4000 token 默认; P0/P1 保住目标章/Scene/总纲, 再裁低层 | 真实长篇数据证明不足时调整, 不提前建动态预算系统 |
| 独立预览 UI | proposal 来源摘要已覆盖首版确认 | 作者需要逐项排除或 working/canonical 频繁切换时 |
| outline 公共入口 | 保持 core 原语“未接产品” | client/agent 的作者旅程确定后复用同一 receipt, 不另建框架 |

## 2. 已落地: 剧情地图 Story Map

### 2.1 数据面(`@novelcraft/store`)

`storyMap(root)` 是纯读、可全量重建的派生读面，不写任何资产。

输入来源(全部文件真相):
- `book.yml` → `book` 标题
- `chapters/*.md` → `chapters`(章节号 + 标题)
- `scenes/*.md` → `scenes`(slug/status/章节覆盖/标题)
- `structure/` 下四类结构资产 → `threads` / `arcs` / `foreshadowing` / `reveals`
- 世界对象 + 结构资产 relations + `related_*_ids` 兼容投影 → `edges`

返回形状(`StoryMap`):
- `book` / `chapters`
- `scenes: StoryMapScene[]`
- `threads` / `arcs` / `foreshadowing` / `reveals`: `StoryMapAsset[]`(带深字段:
  summary、thread_type、起止章、chapter_range、planned_payoff_chapter/scene、
  target_type/id、secret_summary 等)
- `edges: RelationEntry[]`

### 2.2 关系边(ADR-0019 附录 A, 7 类)

`storyMap.edges` = 显式 `relations` 边(`rebuildIndex` 已索引)∪
`related_*_ids` 兼容投影(N17)，并集去重后确定性排序。

| type | 目标 | 允许源 | 语义 |
|---|---|---|---|
| `serves_thread` | thread | scene / arc / foreshadowing / reveal | 服务剧情线 |
| `belongs_to_arc` | arc | scene | Scene 隶属篇章 |
| `reveals_foreshadowing` | foreshadowing | reveal | 回收伏笔 |
| `pays_off_in_scene` | scene | foreshadowing | 伏笔落地 Scene |
| `references_character` | character | thread / arc / scene | 引用人物 |
| `references_entity` | entity | thread / arc / scene / foreshadowing | 引用实体 |
| `references_memory` | memory 事件 id | thread | 引用记忆 |

写入门禁:
- `validateRelations(root, sourceKind, sourceSlug, relations)` 校验形状/type 白名单/源 kind
  白名单/自环/悬空/端点 kind。
- `assertValidRelations(...)` 接入写链：失败抛 `StoreError(VALIDATION_FAILED)`，
  与 adopt fail-closed 一致。
- `reveal.target_id` / `scene.pov_character_id` 等单目标身份锚保留顶层字段，不进 relations。

### 2.3 客户端 UI(`@novelcraft/dsh-client`)

- 挂载位置: 会话头动作 `conversation.session.header.actions`，id
  `novelcraft-story-map`(order 40)。
- 端点: `story/map`，由宿主 handler 调用 `store.storyMap(binding.root)`。
- 视图:
  - 章节列表(可点击钻取到 `ChapterDossier`)
  - 剧情线 / 篇章纲 / 伏笔 / 回收 / 场景分区
  - 关系边分区：按 7 个 type 分组 + 彩色徽章 + 未知 type 兜底 + deprecated 删除线弱化
  - 中英双语 `story.*` 文案
- 安全边界: **纯展示零写操作**; 修订类意图只进收件箱/助手流程。

## 3. 部分落地: 深度导入 Stage 2「地图」

设计文档 §6 把深度导入分为六阶段，其中:

> **Stage 2 · 地图**: 章节地图(确定性) → `compile_phase1a_context`(保留的确定性 helper)
> → 切分 fan-out(每子代理 `scene_slicing` → `stage_candidates`)→ `parallel` 验证子代理核验
> 覆盖/锚点/连续缺口 → **对话点**: 作者可对单章打回重跑 → `adopt(scenes)` 走 fenced commit。

当前 `@novelcraft/imports` 已实现:

| 步骤 | 函数 | 内容步 spec | 说明 |
|---|---|---|---|
| Phase 1a | `sliceChapterBatch` | `scene_slicing` | 逐章切 Scene 候选; 单章失败整章 fallback |
| Phase 1b | `enrichSceneBatch` | `scene_enrichment` | 补全语义字段; 失败空语义进复核 |
| Phase 1c | `fuseSceneBatch` | `scene_fusion` | 成对边界复核; 决策只记录不自动应用 |
| commit | `commitScenes` | — | `runtime.approve` 必经审批; 拒绝 fail-closed |
| 编排 | `runDeepImport` | — | 顺序编排 + checkpoint + trace 事件 + policy 分片 |

已注册但**未接入编排**的 spec:
- `scene_anchor_repair`(catalog §1.2)
- `scene_gap_recovery`(catalog §1.3)

M4 与设计 Stage 2 的差距:
1. 无 `compile_phase1a_context` 确定性 helper; 当前只接受可选的 `phase1aContext` 字符串注入。
2. `runDeepImport` 明确顺序串行，不并行 fan-out(分片尺寸已按 policy 切好，留给 DSH 挂载阶段)。
3. 无 `parallel` 验证子代理对覆盖/锚点/连续缺口做独立核验。
4. 无作者对单章打回重跑的对话点(ralph 修批环)。
5. anchor repair / gap recovery 只注册未调用。

## 4. 未落地: 世界地图册(map atlas)

### 4.1 M4 已沉淀的规格

- `specs/prompts/catalog.md §4.11 map_atlas_plan`:
  - 输入: `world.map_atlas.generate` 编译的 author-full canonical 资料 + RAG `map_atlas`
    证据 + 可选工作稿; 每批 5 个地点提取空间线索。
  - 输出 `AtlasPlan`: 最多 20 页、无环、父级先于子级、默认不深于街道; 每页直接来源 /
    AI 视觉补全 / 冲突 / 标注。
  - 文本规划 temp 0 / max_tokens 4000; 图片 Prompt temp 0.2 / max_tokens 12000。
  - 图片走固定 Image API(`gpt-image-2`)，**不是 llm_step**。
  - 成图不出现文字/字母/数字/方向箭头/距离/比例尺/图例/层级标签。
- `specs/rules/policy-defaults.md`:
  - `map_atlas_plan` 温度与 max_tokens 覆盖键。
  - `budget.map_atlas.max_pages` ≤20、`budget.map_atlas.batch_locations` 每批 5。

### 4.2 当前代码状态

- `@novelcraft/world` 只有对象/待处理读面 + 生成中心五模式; **没有 map 子系统文件**。
- `world/src/specs-world.ts` 注册了 7 个 world spec，**未注册 `map_atlas_plan`**。
- `trace/src/trace.ts` 的 `DeepImportPolicy` 只含导入三键，不承载 map 政策。
- 规划蓝图见 `packages/novelcraft/后续阶段-PLAN.md`(world 包目标含「地图册」catalog §4 的
  11 spec，当前完成五模式 + 页面提案)。

### 4.3 旧引擎参考(归档 tag `old-engine`，只读参考)

旧引擎有完整 map atlas 实现，M4 迁移前可查阅:
- 契约: `git show old-engine:docs/modules/15_map.md`
